# Release notes — v0.4.0 HCL config-file unification

**Status:** Drafted alongside IMPL-0005. To be shipped as forge
v0.4.0 once the downstream forge-registry migration PR (D.6) is open
and `make ci` is green on `main`.
**Semver:** minor bump per IMPL-0005 OQ-8 — pre-1.0 minors are the
right channel for a documented breaking change. Precedent:
v0.3.0 (IMPL-0004 OQ-9).

---

## ⚠️ Breaking change

**Existing v2 YAML configs will not load.** `blueprint.yaml` and
`registry.yaml` are no longer accepted — `forge` rejects them at
load time with a pointer to the migration tool. Run:

```sh
forge migrate config --path <your-registry>
```

against every registry you maintain before upgrading consumers. The
migration guide is [docs/MIGRATION.md](../MIGRATION.md).

If you can't migrate yet, **pin to the previous minor** (the last
release of the YAML config loader, v0.3.x). v0.3.x continues to
load `blueprint.yaml` / `registry.yaml`.

If you are still on v0.2.x (`text/template`), you must run **both**
migrations in order — `forge migrate templates` first, then
`forge migrate config`.

## What changed

Forge's blueprint and registry config files swapped from YAML to
HCL2 (`hashicorp/hcl/v2`). The same grammar that already powered
templates now covers configs, eliminating the YAML-string-of-HCL-source
double-quoting that v0.3.x left behind:

```hcl
# blueprint.hcl — expressions are first-class HCL, not YAML strings
variable "go_module" {
  type        = "string"
  description = "Go module path"
  default     = "github.com/${org}/${project_name}"
}

condition {
  when    = license == "none"
  exclude = ["LICENSE*"]
}
```

The full rationale is in
[DESIGN-0004](../design/0004-unify-config-file-format-after-hcl2-cutover.md).

## Upgrading

1. **Confirm forge version.** The CLI now requires `blueprint.hcl`
   and `registry.hcl`; the `apiVersion` field is gone (the file
   extension is the version signal).
2. **Migrate each registry you maintain:**

   ```sh
   cd path/to/registry
   git status                                   # clean working tree
   forge migrate config --path . --dry-run      # preview
   forge migrate config --path .                # apply
   git diff                                     # review
   git commit -am "migrate: config files to HCL"
   ```

3. **Verify** by scaffolding from each migrated blueprint:

   ```sh
   forge create your-org/api --defaults
   ```

4. **Re-add YAML comments by hand.** The migrator is structural — it
   walks the parsed `Blueprint` / `Registry` and emits clean HCL.
   `# …` lines in the source YAML are not preserved (per IMPL-0005
   OQ-3). Re-apply any author comments after migration.

## New: `forge migrate config`

One-shot YAML→HCL rewriter. Walks the registry, emits a `.hcl`
sibling for every `blueprint.yaml` / `registry.yaml`, then deletes
the original. Drops the `apiVersion` field on emit. Templated fields
(`variable.default`, `condition.when`, `rename` entries) round-trip
with their HCL syntax intact. Output is canonically formatted via
`hclwrite.Format`. Guarded by a dirty-worktree check (override with
`--force`); supports `--dry-run` and `--strict`. Refuses to touch
directories where both `.yaml` and `.hcl` already exist side by side
— clean up the partial migration first.

## Behaviour changes worth knowing

- **No more `apiVersion` field.** The file extension carries the
  version signal. `apiVersion: v2` lines in legacy YAML are dropped
  on emit; new `blueprint.hcl` files do not have an equivalent.
- **`Condition.When` is a parsed `hcl.Expression`** (no longer a
  string). HCL syntax errors in `when = …` now surface at
  `LoadBlueprint` time with file/line/column rather than on first
  evaluation. The original source text is retained on
  `Condition.WhenSource` for round-tripping.
- **Block-shaped lists.** Where v0.3.x YAML had `variables: [ … ]`
  arrays, HCL uses one labelled block per entry: `variable "name"
  { … }`, `blueprint "name" { … }`, `condition { … }`,
  `managed_file "F" { … }`, `rename { entry { … } }`,
  `maintainer { … }`. The block label becomes the `name`/`path`
  field on the in-memory struct.
- **Loader rejects bare YAML.** `forge create` / `forge sync` /
  `forge check` against an un-migrated registry produces a clear
  error: *"YAML config files are no longer supported. Run
  `forge migrate config --path …` …"*.
