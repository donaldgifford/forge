# Release notes draft — HCL2 template engine cutover

**Status:** Draft, ready to paste into the GitHub release whose tag
covers IMPL-0004 Phases A–C.
**Semver:** minor bump (use the `minor` PR label). The change is
breaking in spirit but ships as a 0.x minor per IMPL-0004 OQ-9:
pre-1.0 minors are the right channel for documented breaking
changes.
**Don't ship this release without:** at least one downstream
registry already migrated (see "Before you cut" below).

---

## ⚠️ Breaking change

**Existing v1 blueprints will not load.** Run
`forge migrate templates --path <your-registry>` against every
registry you maintain before upgrading consumers. The migration
guide is [docs/MIGRATION.md](../MIGRATION.md).

If you can't migrate yet, **pin to the previous minor** (the last
release of the `text/template` engine). There will be no
back-compatible 1.x — v1 is end-of-life.

## What changed

Forge's template engine swapped from Go `text/template` to HCL2
(`hashicorp/hcl/v2`). YAML blueprints with embedded `{{ }}` content
for downstream tools (Helm, Argo CD, kustomize) now ship without
escape gymnastics:

```yaml
# templates/deployment.yaml.tmpl — verbatim Helm content survives
name: ${project_name}
replicas: {{ .Values.replicas }}     # ← was `{{ "{{" }} .Values.replicas {{ "}}" }}`
```

The full rationale is in
[ADR-0001](../adr/0001-use-hcl2-as-the-template-engine.md).

## Upgrading

1. **Confirm forge version.** The CLI now requires
   `apiVersion: v2` in `blueprint.yaml` and `registry.yaml`.
2. **Migrate each registry you maintain:**

   ```sh
   cd path/to/registry
   git status                                       # clean working tree
   forge migrate templates --path . --dry-run       # preview
   forge migrate templates --path .                 # apply
   git diff                                         # review
   git commit -am "migrate: blueprints to HCL2"
   ```

3. **Verify** by scaffolding from each migrated blueprint:

   ```sh
   forge create your-org/api --defaults
   ```

4. **Address any `UntranslatedHits`** the tool reports. The most
   common manual fixes are `{{ range }}` / `{{ with }}` blocks and
   three-or-more-arg pipes — see the "Manual fixes" section of
   docs/MIGRATION.md for v1-vs-v2 examples.

## New: `forge migrate templates`

One-shot v1→v2 rewriter. Walks the registry, bumps `apiVersion` in
`blueprint.yaml` and `registry.yaml` to `v2`, rewrites every `.tmpl`
file, and renames `{{varname}}` directories to `${varname}`. Guarded
by a dirty-worktree check (override with `--force`); supports
`--dry-run` and `--strict`.

## Behaviour changes worth knowing

- **Strict-vars mode by default.** Every `${name}` reference must
  correspond to a declared variable. v1 was lenient and substituted
  empty strings for missing keys.
- **`condition.when:` is a bare HCL expression.** Use
  `!use_grpc` instead of `{{ eq .use_grpc "false" }}`.
- **`coalesce(x, "fallback")`** replaces v1 `default`. Argument
  order is unchanged.
- **In-memory variables are `cty.Value`.** Lockfile YAML scalars
  stay scalars on disk; coercion is driven by the declared variable
  type (`internal/lockfile/cty.go`).
